# [같은 숫자는 싫어](https://school.programmers.co.kr/learn/courses/30/lessons/12906)

## Intuition
연속된 동일 숫자를 제거하고, 순서를 유지한 채 결과를 반환해야 한다.<br>
현재 값과 이전 값을 비교하여, 서로 다른 경우에만 결과에 추가하면 된다고 판단했다.<br>
이를 위해 처음에는 스택의 LIFO 특성을 활용하여, 최상단 값과 현재 값을 비교하는 방식으로 접근했다.

---

## Approach
1. 이전 값과의 비교를 위해 `Stack`을 생성한다.
2. 결과를 저장할 `List`를 생성한다.
3. 초기 비교 기준을 설정하기 위해 `arr[0]`을 Stack과 List에 추가한다.
4. `arr[1]`부터 순회하며, Stack의 최상단 값과 현재 값을 비교한다.
5. 값이 서로 다를 경우에만 List에 추가하고 Stack에도 삽입한다.
6. 순회가 끝나면 List를 배열로 변환하여 반환한다.

---

## Complexity
### Time Complexity
O(n), 배열을 한 번 순회한다.

### Space Complexity
O(n), 결과 저장을 위한 리스트를 사용한다.

---

## Code
```
import java.util.*;

public class Solution {
    public Integer[] solution(int[] arr) {
        Stack<Integer> stack = new Stack<>();
        ArrayList<Integer> list = new ArrayList<>();
        stack.push(arr[0]);
        list.add(arr[0]);
        
        for (int i = 1; i < arr.length; i++) {
            if (stack.peek() != arr[i]) {
                stack.push(arr[i]);
                list.add(arr[i]);
            }
        }

        return list.toArray(new Integer[list.size()]);
    }
}
```

## Review
초기에는 문제의 분류가 스택/큐였기 때문에 스택을 활용해 풀이를 구성했다.<br>
하지만 실제로는 이전 값과의 비교만 필요하기 때문에, 스택 없이도 충분히 해결 가능한 문제였다.

다른 사람의 코드를 보니 문제에서 arr의 원소가 0부터 9까지라는 조건을 활용하여, 초기 비교값을 10으로 설정하는 방식도 인상적이었다.<br>
이를 통해 별도의 초기 처리 없이도 동일한 로직을 유지할 수 있었다.

### 리스트만 사용
초기 비교값을 10으로 설정한 뒤, 배열을 순회하며 이전 값과 다를 경우에만 결과에 추가하고 비교값을 갱신한다.
````
import java.util.*;

public class Solution {
    public int[] solution(int[] arr) {
        ArrayList<Integer> list = new ArrayList<>();
        int prevValue = 10;
        
        for (int i = 0; i < arr.length; i++) {
            if (prevValue != arr[i]) {
                list.add(arr[i]);
                prevValue = arr[i];
            }
        }
        
        int[] answer = new int[list.size()];
        for (int i = 0; i < list.size(); i++) {
            answer[i] = list.get(i);
        }

        return answer;
    }
}
````

## Stack이 좋은 선택이 아닌 이유
### LIFO 특성이 필요 없음
Stack은 다음의 상황에서 사용한다. 
- 되돌아가야 할 때 (backtracking)
- 괄호, 중첩 구조 처리 
- 최근 데이터 우선 처리

그러나 이 문제는 `현재 값 vs 직전 값 비교`만 하면 되기에 **Stack의 핵심 특성(LIFO)을 전혀 활용하지 않는다.**

### 불필요한 오버헤드
Stack을 사용하면 다음과 같은 상황이 발생한다. 
- push, peek 같은 연산 추가
- 불필요한 메모리 사용

필요한 건 오직 `prevValue`이다.

### 가독성 저하
변수를 사용하는 것이 훨씬 직관적이고 읽기 쉽다.
````
// Stack 사용
if (stack.peek() != arr[i])

// 변수 사용
if (prevValue != arr[i])
````
