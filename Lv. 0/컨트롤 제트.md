# [컨트롤 제트](https://school.programmers.co.kr/learn/courses/30/lessons/120853)

## Intuition

`"Z"`가 등장하면 직전에 더한 숫자를 취소해야 한다.<br>
가장 최근에 추가한 값을 제거해야 하므로 **LIFO(Last In First Out)** 구조인 스택을 사용하기 적합하다.

---

## Approach

1. 숫자를 저장할 스택을 생성한다.
2. 공백을 기준으로 문자열을 분리한다.
3. 각 토큰을 순회한다.
   - "Z"이면 스택의 최상단 값을 제거한다.
   - 숫자라면 정수로 변환하여 스택에 저장한다.
4. 순회가 끝난 뒤 스택에 남아 있는 값들의 합을 반환한다.

---

## Complexity
### Time Complexity
O(n) - 모든 토큰을 한 번씩 순회한다.

### Space Complexity
O(n) - 최악의 경우 모든 숫자가 스택에 저장될 수 있다.

---

## My Solution
```
import java.util.*;

class Solution {
    public int solution(String s) {
        Stack<String> stack = new Stack<>();
        
        StringTokenizer st = new StringTokenizer(s);
        while (st.hasMoreTokens()) {
            String now = st.nextToken();
            
            if (now.equals("Z") && !stack.isEmpty()) stack.pop();
            else stack.push(now);
        }
        
        int answer = 0;
        while(!stack.isEmpty()) {
            answer += Integer.parseInt(stack.pop());
        }
        return answer;
    }
}
```

---

## Review

- Stack<String> → Deque<Integer>
  - Stack은 레거시 클래스이고, 숫자를 문자열로 저장할 필요 없이 파싱 시점을 앞으로 당길 수 있다.
- StringTokenizer → split()
  - 더 현대적이고 가독성이 좋다.
- 합산을 마지막에 따로 하지 않고 스택에서 꺼낼 때 바로 처리하면 코드가 간결해진다.

---

## Revised Solution
````
import java.util.*;

class Solution {
    public int solution(String s) {
        Deque<Integer> stack = new ArrayDeque<>();
        
        for (String token : s.split(" ")) {
            if (token.equals("Z")) stack.pop();
            else stack.push(Integer.parseInt(token));
        }
        
        return stack.stream().mapToInt(Integer::intValue).sum();
    }
}
````

### 핵심 변경 사항
| 항목         | 기존 | 개선 |
|-----------|---|---|
| **자료구조**  | Stack<String> | Deque<Integer> (ArrayDeque) |
| **토크나이징**   | StringTokenizer | split(" ") |
| **파싱 시점**   | 마지막 합산 시 | push 시점에 즉시 변환 |
| **합산** | while 루프 | stream().mapToInt().sum() |

## Deque (Double-Ended Queue)

양쪽 끝에서 삽입/삭제가 가능한 자료구조이다.

````
앞(Front)  ←→  [ 1 | 2 | 3 | 4 | 5 ]  ←→  뒤(Rear)
````


### Stack vs Queue vs Deque 비교
| 항목 | Stack | Queue | Deque |
|------|-------|-------|-------|
| 삽입 | 뒤만 | 뒤만 | 앞/뒤 둘 다 |
| 삭제 | 뒤만 | 앞만 | 앞/뒤 둘 다 |
| 구조 | LIFO | FIFO | 둘 다 가능 |


### Java에서 주요 메서드
```
Deque<Integer> deque = new ArrayDeque<>();

// 삽입
deque.push(1);      // 앞에 추가 (Stack처럼)
deque.addFirst(1);  // 앞에 추가
deque.addLast(1);   // 뒤에 추가

// 삭제
deque.pop();        // 앞에서 제거 (Stack처럼)
deque.pollFirst();  // 앞에서 제거
deque.pollLast();   // 뒤에서 제거

// 조회 (제거 없이)
deque.peek();       // 앞 요소 확인
deque.peekFirst();  // 앞 요소 확인
deque.peekLast();   // 뒤 요소 확인
```

### Java에서 Stack 대신 Deque를 쓰는 이유
`Stack`은 `Vector`를 상속한 레거시 클래스라 모든 연산이 **synchronized(동기화)** 되어 있다. 단일 스레드 환경에서는 불필요한 오버헤드가 생기기 때문에, Java 공식 문서도 `ArrayDeque` 사용을 권장한다.

```
// 권장하지 않음
Stack<Integer> stack = new Stack<>();

// 권장
Deque<Integer> stack = new ArrayDeque<>();
```

### 구현체 종류
| 구현체 | 특징 |
|--------|------|
| `ArrayDeque` | 배열 기반, 일반적인 경우 성능 우수 |
| `LinkedList` | 연결 리스트 기반, 중간 삽입/삭제에 유리 |
