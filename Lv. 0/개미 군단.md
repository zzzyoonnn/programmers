# [개미 군단](https://school.programmers.co.kr/learn/courses/30/lessons/120837)

## Intuition

이전에 풀었던 [예산](https://github.com/zzzyoonnn/programmers/blob/main/Lv.%201/%EC%98%88%EC%82%B0.md) 문제와 유사한 방식으로 접근했다.<br>
사냥감의 체력을 최소 병력으로 줄여야 하므로, 공격력이 높은 개미부터 사용하는 그리디(Greedy) 전략을 적용한다.

---

## Approach

1. 개미의 공격력을 담은 배열을 생성한다.
2. 공격력이 높은 개미부터 확인한다.
3. 현재 체력에서 해당 공격력이 몇 번 사용 가능한지 계산한다.
4. 사용한 만큼 병력을 증가시키고, 남은 체력을 갱신한다.
5. 모든 공격력을 순회한 뒤 병력 수를 반환한다.

---

## Complexity
### Time Complexity
O(hp) - 개미의 공격력 종류가 고정되어 있어 항상 일정한 횟수만 반복한다.

### Space Complexity
O(1) - 추가적인 자료구조를 사용하지 않는다.

---

## My Solution
```
class Solution {
    public int solution(int hp) {
        int[] power = {5, 3, 1};
        
        int index = 0;
        int answer = 0;
        while (hp > 0) {
            if (power[index] <= hp) {
                answer++;
                hp -= power[index];
            } else index++;
        }
        return answer;
    }
}
```

---

## Review

거스름돈 문제와 동일한 그리디 패턴으로 해결할 수 있다.

다만 현재 방식은 공격력을 한 번씩 차감하기 때문에 반복 횟수가 많아질 수 있으며,<br>
`index`가 배열 범위를 벗어날 가능성도 존재한다.

이를 `/`와 `%` 연산으로 개선하면 한 번에 필요한 개미 수를 계산할 수 있어 코드가 더욱 간결해진다.

---

## Revised Solution
````
class Solution {
    public int solution(int hp) {
        int answer = 0;
        int[] power = {5, 3, 1};
        
        for (int p : power) {
            answer += hp / p;
            hp %= p;
        }
        
        return answer;
    }
}
````

### 핵심 변경 사항
| | 기존 | 개선 |
|---|---|---|
| **방식** | while + index 증가 | for-each + 나눗셈 |
| **안전성** | index 범위 초과 위험 | 위험 없음 |
| **가독성** | 반복 차감 방식 | `/`, `%` 연산으로 직관적 처리 |
| **시간복잡도** | O(hp) | O(1) |

## O(hp)인 이유

기존 코드의 반복 횟수는 입력 배열의 크기가 아니라, 실제로 hp를 얼마나 차감하느냐에 따라 달라진다.

예를 들어:
- hp = 999: while문이 엄청 많이 반복될 수 있음
- hp = 5: 금방 끝남

즉, 반복 횟수가 hp에 비례한다.
````
Time Complexity: O(hp)
````

개선 코드에서는 배열 길이가 항상 3으로 고정되어 있어서 입력 크기와 관계없이 딱 3번만 돈다.
````
Time Complexity: O(1)
````

| 코드             | 시간복잡도 | 이유            |
| -------------- | ----- | ------------- |
| while로 1씩 차감   | O(hp) | hp 크기에 비례해 반복 |
| for-each 3번 반복 | O(1)  | 배열 크기가 고정(3)  |

만약 공격력 종류가 가변적이어서 다음과 같았다면<br>
개선 코드도 O(n)이라고 표현했을 것이다.
````
int[] power = new int[n];
````
