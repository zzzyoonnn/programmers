# [124 나라의 숫자](https://school.programmers.co.kr/learn/courses/30/lessons/12899)

## Intuition

문제의 124 나라 숫자 체계를 보면, 일반적인 3진법과 유사하지만 `0` 대신 `4`를 사용한다는 특징이 있다.<br>
즉, `3으로 나눈 나머지`를 기준으로 다음과 같은 규칙이 성립한다.

- 나머지 1 → 1
- 나머지 2 → 2
- 나머지 0 → 4

다만, 나머지가 `0`인 경우는 일반적인 진법 변환과 다르게 처리해야 한다.
예를 들어 `3`은 `10`이 아니라 `4`가 되어야 하므로, `4`를 추가한 뒤 몫에서 `1`을 빼주는 보정 과정이 필요하다.

숫자는 뒤 자리부터 생성되므로 `StringBuilder`를 사용해 값을 추가하고, 마지막에 `reverse()`로 뒤집어 반환한다.

| 숫자 | 몫 | 나머지 | 124 나라 |
| -- | - | --- | ------ |
| 1  | 0 | 1   | 1      |
| 2  | 0 | 2   | 2      |
| 3  | 1 | 0   | 4      |
| 4  | 1 | 1   | 11     |
| 5  | 1 | 2   | 12     |
| 6  | 2 | 0   | 14     |
| 7  | 2 | 1   | 21     |
| 8  | 2 | 2   | 22     |
| 9  | 3 | 0   | 24     |
| 10 | 3 | 1   | 41     |


---

## Approach
1. 결과 문자열을 저장할 `StringBuilder`를 생성한다.
2. `n > 0` 동안 반복하며:
   - `n % 3` 값을 구한다.
   - 나머지가 `0`, `1`, `2`일 때 각각 `4`, `1`, `2`를 추가한다.
   - 나머지가 `0`이면 `n = n / 3 - 1`로 보정한다.
   - 그 외에는 `n /= 3`을 수행한다.
3. 뒤에서부터 숫자를 생성했으므로 마지막에 `reverse()` 후 반환한다.

---

## Complexity
### Time Complexity
O(log₃n) - 반복마다 n을 3으로 나누므로, 반복 횟수는 log₃n에 비례한다.

### Space Complexity
O(m * n) - 결과 문자열을 저장하기 위한 공간이 필요하며, 생성되는 자릿수 또한 log₃n 크기이기 때문이다.

---

## My Solution
```
class Solution {
    public String solution(int n) {
        StringBuilder sb = new StringBuilder();
        
        while (n > 0) {
            
            if (n % 3 == 0) {
                sb.append(4);
                n = n / 3 - 1;
            } else {
                if (n % 3 == 1) sb.append(1);
                else if (n % 3 == 2) sb.append(2);
                
                n /= 3;
            }
        }
        
        return sb.reverse().toString();
    }
}
```

## Review

전반적으로 로직은 정확하고 깔끔하게 작성되었다.<br>
특히 `3으로 나누어 떨어지는 경우`를 별도로 처리한 점이 핵심 아이디어를 잘 반영하고 있다.

다만 몇 가지 개선 포인트가 있다.

### 개선 포인트

- 매직 넘버 제거
   - `1`, `2`, `4`를 직접 사용하기보다 배열로 관리하면 의미가 더 명확해진다.
- 중복 계산 제거
   - `n % 3`을 여러 번 계산하기보다 변수에 저장해 재사용할 수 있다.
- 분기 구조 단순화
   - 나머지 값을 기반으로 바로 문자를 선택하면 조건문을 더 간결하게 만들 수 있다.

## Revised Solution
````
class Solution {
    private static final char[] DIGIT = {'4', '1', '2'};
    
    public String solution(int n) {
        StringBuilder sb = new StringBuilder();
        
        while (n > 0) {
            int remainder = n % 3;
            sb.append(DIGIT[remainder]);
            
            n = (remainder == 0) ? n / 3 - 1 : n / 3;
        }
        
        return sb.reverse().toString();
    }
}
````

알고리즘 복잡도는 기존과 동일하게 `O(log₃n)`이다.
입력 범위(`n ≤ 3,000,000`)에서는 반복 횟수가 많지 않기 때문에, 성능 차이보다는 가독성과 유지보수성 개선에 의미가 있다.

즉, 이 문제에서의 리팩토링 포인트는 더 빠르게보다는 **더 읽기 쉽게**에 가깝다.

### 주요 개선 사항
| 항목 | 기존                 | 개선                      |
|------|--------------------|-------------------------|
| 매직 넘버 | 코드 내 `1`, `2`, `4` 직접 기입 | `DIGITS` 배열로 의미 명시      |
| 나머지 계산 | `n % 3` 반복 호출      | `remainder` 변수로 한 번만 계산 |
| 분기 구조 | 중첩 `if / else if`      | 배열 인덱싱 + 삼항 연산자로 단순화    |
