# [카카오프렌즈 컬러링북](https://school.programmers.co.kr/learn/courses/30/lessons/1829)

## Intuition
그림은 상하좌우로 연결된 같은 색상의 영역으로 구성된다.<br>
각 위치를 기준으로 **같은 색이 연결된 영역을 탐색**하기 위해 DFS를 사용한다.<br>
방문 여부를 기록하여 이미 탐색한 영역을 중복으로 세지 않도록 한다.

---

## Approach
1. `visited` 배열을 생성하여 방문 여부를 관리한다.
2. 전체 배열을 순회하며, 아직 방문하지 않았고 색상이 0이 아닌 위치를 찾는다.
3. 해당 위치에서 DFS를 수행하여 같은 색으로 이루어진 영역의 크기를 계산한다.
4. DFS가 시작될 때마다 영역의 개수를 증가시키고, 탐색 결과로 얻은 크기로 최대 넓이를 갱신한다.
5. 모든 탐색이 끝난 후, 영역의 개수와 최대 넓이를 반환한다.

---

## Complexity
### Time Complexity
O(m * n), 각 칸은 최대 한 번만 방문하며 DFS 또한 각 칸을 한 번씩만 탐색한다.

### Space Complexity
O(m * n), `visited` 배열을 사용하고 재귀 호출을 사용한다.

## My Solution
```
class Solution {
    static int rows, cols, numberOfArea, size;
    static int[][] image;
    static boolean[][] visited;
    static int[] dx = {1, -1, 0, 0}, dy = {0, 0, 1, -1};
    
    public int[] solution(int m, int n, int[][] picture) {
        rows = picture.length;
        cols = picture[0].length;
        image = new int[rows][cols];
        visited = new boolean[rows][cols];
        
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                image[i][j] = picture[i][j];
            }
        }
        
        numberOfArea = 0;
        int maxSizeOfOneArea = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (!visited[i][j] && image[i][j] != 0) {
                    size = 0;
                    numberOfArea++;
                    dfs(i, j, image[i][j]);
                    
                    maxSizeOfOneArea = Math.max(maxSizeOfOneArea, size);
                }
            }
        }

        return new int[]{numberOfArea, maxSizeOfOneArea};
    }
    
    static void dfs(int x, int y, int color) {
        size++;
        visited[x][y] = true;
        
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k];
            int ny = y + dy[k];
            
            if (isInBounds(nx, ny) && !visited[nx][ny] && image[nx][ny] == color) {
                dfs(nx, ny, color);
            }
        }
    }
    
    static boolean isInBounds(int x, int y) {
        return x >= 0 && x < rows && y >= 0 && y < cols;
    }
}
```

---

## Review
기존 구현은 동작은 올바르지만, 구조적으로 개선할 수 있는 부분이 있다.

- `image` 배열은 불필요 — `picture`를 직접 사용 가능
- `static` 필드 남용 — 상태 공유로 인해 버그 가능성 증가
- 전역 변수(`size`) 사용 — 함수의 독립성이 떨어짐


### static 필드 방식의 단점

| 상황 | 영향 |
|------|------|
| 멀티스레드 환경 | static 필드 공유로 race condition 위험 |
| Solution 재사용 | 이전 호출의 상태가 남아있을 수 있음 |
| 테스트 | 독립적인 단위 테스트가 어려움 |

## Revised Solution
````
class Solution {
    static int rows, cols;
    static boolean[][] visited;
    static int[] dx = {1, -1, 0, 0}, dy = {0, 0, 1, -1};
    
    public int[] solution(int m, int n, int[][] picture) {
        rows = picture.length;
        cols = picture[0].length;
        visited = new boolean[rows][cols];
        
        int numberOfArea = 0;
        int maxSizeOfOneArea = 0;
        for (int i = 0; i < m; i++) {
            for (int j = 0; j < n; j++) {
                if (!visited[i][j] && picture[i][j] != 0) {
                    numberOfArea++;
                    int size = dfs(i, j, picture[i][j], picture);
                    
                    maxSizeOfOneArea = Math.max(maxSizeOfOneArea, size);
                }
            }
        }

        return new int[]{numberOfArea, maxSizeOfOneArea};
    }
    
    static int dfs(int x, int y, int color, int[][] picture) {
        int size = 1;
        visited[x][y] = true;
        
        for (int k = 0; k < 4; k++) {
            int nx = x + dx[k];
            int ny = y + dy[k];
            
            if (isInBounds(nx, ny) && !visited[nx][ny] && picture[nx][ny] == color) {
                size += dfs(nx, ny, color, picture);
            }
        }
        
        return size;
    }
    
    static boolean isInBounds(int x, int y) {
        return x >= 0 && x < rows && y >= 0 && y < cols;
    }
}
````
DFS 문제는 **공유 상태에 의존하기보다 값을 반환하는 방식으로 구현할 때 훨씬 깔끔해진다.**

이 방식은 단순히 가독성을 높이는 것을 넘어,
함수의 동작을 더 명확하게 만들고 테스트 및 재사용도 용이하게 해준다.

### 주요 개선 사항
| 항목     | 기존                  | 개선               |
| ------ | ------------------- | ---------------- |
| 데이터 처리 | `image` 배열을 별도로 복사  | `picture`를 직접 사용 |
| 상태 관리  | 전역 `size` 변수 사용     | DFS 반환값으로 처리     |
| 코드 구조  | `static` 필드 과도하게 사용 | 공유 상태 최소화        |
| 가독성    | 암묵적인 상태 변화          | 반환값 기반의 명확한 흐름   |
